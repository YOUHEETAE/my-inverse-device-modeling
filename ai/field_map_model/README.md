# Field-map model

Fixed-bias (`Vg=3 V`, `Vd=3 V`) spatial surrogate for potential, carriers,
electric field, current density, and SRH recombination. The training dataset
keeps node-centered and element-centered quantities separate and reuses the
locked curve-model device split.

Prepare and validate the HDF5 dataset with:

```powershell
conda activate devsim_env
python -m ai.field_map_model.data.prepare_dataset
```

Generated local artifacts are written under
`ai/model_artifacts/field_map_model/dataset/` and are ignored by Git:

- `fieldmap_dataset.h5`: deduplicated structure meshes and per-case fields
- `raw_manifest.csv`: source case inventory
- `split_manifest.json`: exact curve-model split reuse
- `raw_integrity_report.json`: mesh, field, and LDD checks
- `distribution_report.json`: train-only field statistics

Screen target transforms and scalers without touching the test split:

```powershell
python -m ai.field_map_model.training.screen_preprocessing
```

`NetDoping` is treated as a known local input, not as a learned output. The
screening compares raw, `asinh`, and signed-`log1p` target representations with
standard/robust scaling on validation samples.

The two-seed screening selected signed-`log1p(q10)` for the signed node target
and `asinh(q10)` for signed element targets; carrier densities use `log1p` and
potential remains linear. Every field uses its own standard scaler. The frozen
recipe is recorded in `configs/selected_preprocessing.json`; its numeric scale,
mean, and standard-deviation values must be fitted on the eventual training
samples only and saved with the trained model.

Train the first coordinate-based node/element baseline with:

```powershell
python -m ai.field_map_model.training.train_coordinate_mlp
```

The command writes separate model weights, feature scalers, target transforms,
and validation reports below
`ai/model_artifacts/field_map_model/baselines/coordinate_mlp/`.

Compare raw validation maps against model predictions interactively:

```powershell
python ai/field_map_model/tools/visualization_fieldmap_model.py
```

The viewer shows `Raw TCAD`, `Coordinate MLP`, and `Model - Raw` with a shared
raw/prediction color range. It supports every node/element field, physics-aware
or linear display transforms, and robust/full color ranges. Test devices are
intentionally excluded.

Run all 386 validation maps, physics consistency checks, and a regenerated
Gmsh-mesh inference smoke test with:

```powershell
python ai/field_map_model/tools/audit_fieldmap_baseline.py
```

This audit intentionally does not load the final test split.

Render the three worst validation devices for every predicted field with:

```powershell
python -m ai.field_map_model.evaluation.visualize_worst_cases
```

For a new structure, `generate_gmsh_mesh(...)` creates a variable-size triangle
mesh and `FieldMapPredictor.predict(...)` fills its node- and element-centered
fields using analytic NetDoping as the local material input.

Train the bulk/channel-focused element candidate without retraining the node
baseline with:

```powershell
python -m ai.field_map_model.training.optimize_element_mlp
```

The candidate keeps the same MLP size and point budget, but stratifies bulk
samples by depth and gives moderate loss emphasis to electric field and
`ElectronCurrent_y`.

Train the same candidate with an additional electric-field direction constraint
against the triangle gradient of TCAD potential with:

```powershell
python -m ai.field_map_model.training.optimize_element_physics
```

When the validation-selected physics candidate exists locally,
`visualization_fieldmap_model.py` loads it by default; otherwise it falls back
to the original coordinate-MLP baseline. `--model-dir` can always override the
selection explicitly.

After the one-time final test, create the Git-trackable inference package with:

```powershell
python ai/field_map_model/tools/package_final_fieldmap_model.py
```

The packager verifies the node and element checkpoint hashes against the final
test marker before copying weights, fitted scalers, transforms, and reports to
`ai/model_artifacts/field_map_model/final/coordinate_mlp_physics/`.

View only fields generated by the final model, without loading raw TCAD maps:

```powershell
python ai/field_map_model/tools/visualization_fieldmap_model_output.py
```

The model-only viewer follows the TCAD field-map GUI: select or directly type
continuous `L`, `T`, `B`, `SD`, `LDD` values, plus field type, scale, and color
range. Sweep values remain available as suggestions. It generates/caches a Gmsh
mesh, fills it with the final node/element models, and also provides derived
field/current magnitudes and approximate 1D energy-band cuts. Values outside
the training ranges are allowed but are marked as extrapolation.

Use both finalized AI models from one shared-parameter, tabbed GUI with:

```powershell
python ai/tools/visualization_models.py
```

The common `L`, `T`, `B`, `SD`, and `LDD` values drive both the I–V curve tab
and the structure/field-map tab.

The I–V tab keeps an editable curve list: add, update, select, or remove as many
device configurations as needed. Device identity uses a stable hue group,
IdVd/IdVg use related hue tints, and low/high fixed voltages use
light-dashed/dark-solid variants.
